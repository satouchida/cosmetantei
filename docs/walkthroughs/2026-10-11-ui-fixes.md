# Walkthrough: quick-reply remapping and UI fixes

Date: 2026-10-11. Builds on `75c66d2` (pnpm, Next 16, Tailwind 4, TypeScript 7) and `430fe1a`
(Clef chat gate).

## The problem

Every quick-reply button sent its label to `/api/chat` as if the user had typed it. Most buttons
are UI actions, not questions, so the server couldn't act on them:

- 「🚨 このアイテムで肌荒れした（原因を特定）」 should add the analyzed product to the
  "bad" list, but the server only saw the text and ran a product search for it.
- 「🔍 別のコスメを調べる」 and similar buttons are requests to type a product name, but they
  were searched as if they were product names.
- The example buttons (「⚡️ メラノCCで赤みが出た」) sent the whole sentence to the product
  search, which returned poor matches.
- To keep these labels from being refused by the gate, `chat-gate.ts` had a 26-entry table that
  let them skip Clef. Anyone who typed one of those labels by hand skipped the gate too.

## What changed

### Buttons are handled in the browser

`src/components/chat/quick-replies.ts` (new) maps each label to an action:

| Action | Buttons | What happens |
| --- | --- | --- |
| `scanner` | any label containing 「バーコード」 | opens the barcode scanner |
| `send` | the example product buttons | sends a clean product name (「メラノCC」, 「キュレル 泡洗顔料」, 「トリデン セラム」) |
| `add_analyzed` | 「このアイテムで肌荒れした」, 「普段安全に使えている」 | adds the product from that message's analysis card to the bad or safe list |
| `pick_from_cards` | 「この中のアイテムで…」 | explains how to use the buttons on the candidate cards |
| `reset` | 「🔄 リセットする」 | clears both lists |
| `prompt_input` | 「肌荒れしたコスメを入力する」, 「商品名で検索する」 and the other "search for another" buttons | shows what to type and focuses the input |
| `server` | everything else | sent to `/api/chat` unchanged |

`ChatContainer.tsx` calls `handleQuickReply(label, message)`. Local actions add the button
press and a fixed reply to the chat with `appendLocalExchange()`, with no network request.
Scanner buttons work at any time. Other buttons are ignored while a reply is loading, so
messages can't arrive out of order.

When a product is already in a list, `handleAddToBad` and `handleAddToSafe` now return
`false`. The chat then says 「すでに登録されています」, matching the toast, instead of
「追加しました」.

### The gate bypass shrank to two labels

`QUICK_REPLY_INTENTS` in `chat-gate.ts` now lists only the two buttons that still reach the
server, both `find_alternative`:

- 「💡 おすすめの低刺激アイテムは？」
- 「🔍 この成分が入っていないコスメを探す」

If someone types any other button label by hand, it goes through Clef like normal text.

### Dead buttons removed

`route.ts` no longer offers 「📝 全成分を直接入力する」 or 「⚠️ 他の注意成分は？」. The app has no
ingredient-label input yet (see `docs/review/03-other-upgrades.md`, Product). The second button
re-ran a search with no new information.

### `pnpm dev` works on Next 16

Next 16 passes Node flags to its child process through `NODE_OPTIONS`, and Node rejects
`--env-file-if-exists` there. The old script failed at startup with this error:

```
--env-file-if-exists= is not allowed in NODE_OPTIONS
```

`scripts/dev.mjs` replaces that flag. It:

1. moves to the project root, so it works when started from any folder;
2. loads `.dev.vars` with `process.loadEnvFile` when the file exists;
3. starts `next dev -p 3001`, passing any extra arguments through.

On shutdown, it forwards SIGTERM to Next. It ignores SIGINT, because the terminal already sends
Ctrl+C to Next, and a second signal makes Next force-quit.

### Lint warnings cleared

After `75c66d2`, lint still reported 28 warnings, mostly unused imports. Now it reports none:

- unused imports and variables removed;
- `catch (e)` with an unused `e` changed to `catch {}`;
- `BarcodeScannerModal` lost an unused `isScanning` state;
- the scanner's open/close effect keeps an `exhaustive-deps` disable, with a comment
  explaining why;
- `getServicePurposeExplanation()` dropped its unused parameter.

## Tests

`tests/test_suite.ts` has 47 tests:

- **Test 37** collects every quick-reply label in the app. It checks that each label is
  handled in either the browser or the server table, that neither list has stale labels, and
  that every label in the server table maps to `server` in the browser.
- **Test 47** checks the action for each kind of button.
- **Test 39** now uses a label that still reaches the server.

## Review

**`code-improver` findings, all fixed:**

- The duplicate-add mismatch between the chat and the toast.
- Buttons could be pressed while a reply was loading.
- The gate bypass through typed labels; this is why the server table now has only two labels.
- Launcher hardening: works from any folder, clear error if Next can't start, Ctrl+C sent only
  once.

None were declined.

## `AGENTS.md`

`next dev` generates `AGENTS.md`, a generic note telling AI coding assistants to read the
Next docs in `node_modules/next/dist/docs/`. It has nothing specific to this project, and
`next dev` writes it again whenever it's missing, so it's in `.gitignore` instead of the repo.
To stop Next generating it, set `agentRules: false` in `next.config.mjs`.
