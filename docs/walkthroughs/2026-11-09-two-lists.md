# Two lists: 肌荒れしたコスメ and 使えているコスメ (2026-11-09)

The plan is [docs/plans/two-lists.md](../plans/two-lists.md). The owner found 普段使えている and
今使っている hard to tell apart when registering, and most products belonged in both.

## What the user sees

- **Registering** has two buttons everywhere (search tray, suggestion cards, analysis card, chat
  replies): 「肌荒れした」 and 「使えている」. The 「今使っている」 button is gone.
- **The sidebar** has two sections.
  - 肌荒れしたコスメ: with the note 「このリストは保存しません。ページを閉じると消えます。」
  - 使えているコスメ: each product shows the date it was added and a 「今も使っている」 switch.
    Off reads 「以前使っていた（組み合わせチェックには使いません）」. 「組み合わせをチェック」
    counts only products in use.
- **The 3-month check** applies only to products in use and offers 「今も使っている」 (resets the
  date) or 「もう使っていない」 (switches it off; the product stays for the comparison).
- **Clearing** names the list: 「肌荒れしたコスメのリストをクリア」 and
  「使えているコスメのリストをクリア」, each under its own section and each behind a confirmation
  dialog with a red 「クリアする」. The chat's 「🔄 リセットする」 clears 肌荒れ only and says so.
- **One list per product**: registering a product that is in the other list opens a dialog with
  「…に移す」, 「…から削除」 and 「やめる」.
- **Saving reminder**: the first comparison result of a page session, while 肌荒れ has products
  and the lists changed since the last export, opens 「リストを画像で保存しませんか？」 with
  「画像で保存する」, 「あとで」 and 「今後このお知らせを表示しない」.

## How it works

- `src/lib/usable-products.ts` (was `current-use.ts`): entries are `{ product, addedAt, inUse }`,
  saved under `cosmetantei:usable:v1`. `sessionOnly` entries (the dev sample) and typed or
  seller-text products are kept in memory only. `routineFromLists` builds what the server gets:
  `safeProducts` = every usable product, `currentlyUsing` = products in use. The server is
  unchanged apart from wording.
- `src/lib/client/browser-store.ts` gained `legacyKey`: on the first read, if the new key is empty
  and `cosmetantei:current-use:v1` has a value, it is read, written under the new key and deleted.
  If the write fails, the old key is kept so the move is tried again next time.
- `src/lib/client/export-reminder.ts`: the 「表示しない」 setting (`cosmetantei:export-reminder:v1`
  = `off`) and `shouldOfferExport`. ChatContainer calls it when a reply with a differential result
  arrives.
- `src/lib/routine-share.ts`: image data version 2 (`{ bad, usable }`) and links `{ b, u }`.
  Version 1 files and links are still read: 今使っている products keep their date and are in use;
  普段使えている-only products are read as 以前使っていた; anything also in 肌荒れ stays in 肌荒れ.
- New dialogs: `ChoiceDialog` (clear confirmation, move/remove) and `ExportReminderDialog`, both
  in `/dev/gallery`. `design.ts` gained `buttonDanger`; the registration grid is two columns.
- Legal: the privacy policy 第2条第4号・第5号・第6号, 第7条3. and 第8条第2項, and the terms
  第2条第3号 and 第6条第2項, from
  `docs/legal/privacy-policy-two-lists-draft.md` after the audit. The shown 最終改定日 now comes from
  `LEGAL_REVISED` (2026-11-09); the consent version `LEGAL_VERSION` is unchanged, so users are not
  asked to agree again.

## Code review (code-improver)

Applied:
- **High:** moving a product into a full list removed it from both lists. Now the full check comes
  before the move/remove question, and the move itself checks the limit again and removes nothing
  when it can't add.
- **Medium:** the save reminder read the lists and open dialogs from before the request was sent
  (it runs after the reply arrives). It now reads the latest values from a ref, and the mobile
  drawer counts as an open dialog.
- **Medium:** the 肌荒れ list's duplicate and limit checks read the render's value, so two quick
  taps could add twice. All changes go through `updateBad` with a ref holding the latest list.
- **Medium:** another tab could add a product to 使えているコスメ that this tab has in 肌荒れ. This
  tab now shows such a product in 肌荒れ only (not written back to storage).
- **Low:** sample products are left out of the image and link; the in-use switch keeps the same
  visible text 「今も使っている」, with the 以前使っていた note outside it (WCAG 2.5.3).

Declined:
- Clamping a future `addedAt` in `parseUsable`: only this app writes the key, and the image
  import already clamps dates from outside.
- Counting a cancelled export as "not exported": opening the export dialog already shows the
  user how to save, so the reminder after it would repeat itself.

## Second-model review (Gemini, /antigravity:review)

Applied, after checking each against the code:
- **Export image:** products that aren't saved (typed labels, shop descriptions) were still drawn on
  the image and counted, although the dialog says they are left out. The image surface now uses
  the same filter as the data.
- **Mobile drawer:** a dialog opened from the drawer (list clear) lost Tab to the drawer's key
  handler, and Escape closed the drawer too. The drawer now leaves keys to an open dialog. After
  clearing, focus moves to that list's heading (the menu button is not reachable while the drawer
  is open).
- **Another tab:** registering as 使えている a product this tab has in 肌荒れ showed "already
  registered" when another tab had saved it; it now asks to move or remove.
- **Reminder:** it counts only 肌荒れ products that go into the image (typed labels alone don't
  trigger it), never shows before consent, and follows the 「表示しない」 setting changed in another
  tab (the setting is now subscribed).

Not changed: a product removed from 肌荒れ in this tab reappears in 使えているコスメ if another tab
saved it there; that is the other tab's own registration, not a lost removal. The `metaById` edge
case in `twoLists` (a malformed first duplicate lending its date to a valid later one) stays: only
dates and the in-use flag of the same product are affected.
